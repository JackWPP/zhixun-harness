# 企业赛总体优化说明：0.15.0.dev1

日期：2026-11-27

作者：Arthur

本候选基于公开主线 `17cc307b10caed360405d739bdfb09f457910bad`，该主线运行版本为 v0.14.12。
此前的本地 C 候选为 0.14.13.dev1；本轮在独立副本中继续整合为 **0.15.0.dev1**。
此文描述当前代码、公开数据上的开发期证据与仍需验证的环节。**本候选尚未部署到比赛平台，
没有新的平台正式成绩，也不能用公开验证指标直接计算客观评分或总分增量。**

## 1. 本轮解决的问题

| 项目 | 原公开主线中的问题或限制 | 当前候选的处理 |
|---|---|---|
| A 气体识别 | 漂移策略可覆盖原有选择；整体 F1 可能掩盖个别类别退步 | 所有候选选择与策略覆盖之后，再做整体和受支持类别的最终保持检查 |
| B 轴承寿命 | 默认包含从头训练候选，开销较大；总体改善可能来自样本占多数的轴承 | 默认改为从实际父 checkpoint 小步续训，保留父模型参数、归一化与优化器；检查总体与轴承分组风险 |
| C 发动机寿命 | NASA 口径不统一；先生成候选、最后强制 retain；整体改善不能保证 FD 子集改善 | 使用官方 NASA 总和口径；一次 10 epoch 续训后生成保守权重更新；全局、FD 和固定 RUL 分组共同检查 |
| 重复计算 | 相同父模型与相同训练内容可能反复 fit；不同后处理也可能重复相同训练 | 缓存训练结果，当前验证集始终重新测量；磁盘缓存有文件数和字节预算 |
| 构建与追溯 | SDK、线程默认值及镜像配置可能因入口不同而不一致 | SDK 1.0.5；直接 Python 入口提前设置线程默认值；两条构建路径生成来源清单 |

默认路由仍为 A 使用 kernel，B/C 使用 pipeline；C 高效模式与显式 retain 探针走确定性路径。
正式协议仍要求真实模型网关调用。离线替身宿主验证不代表已验证真实网关费用、延迟或模型行为。

## 2. A：把最终类别保护放在所有策略之后

最终检查在同一公开验证投影上重新测量父模型和准备部署的候选，避免仅信任控制器先前给出的选择。
目前 A 的 `margin=0.004`，受保护类别要求样本数至少为 `max(10, ceil(验证样本数×5%))`。
检查同时约束：

- 整体 Macro-F1 相对父模型下降不超过 0.004；
- 受支持类别的平均 F1 下降不超过 0.004；
- 任一受支持类别 F1 下降不超过 0.008。

保留父模型时同时保留已验证的父后处理，父模型指标也以相同后处理复测。
父 metadata 必须通过 checkpoint SHA 绑定与参数校验；不能只保留权重却清空上一轮阈值等配置。
检查失败则选择父模型。这里允许明确的小幅容差，不能写成“所有类别绝不退步”。
它是公开数据上的点估计保护，不是独立置信区间，也不能证明隐藏漂移阶段安全。
不同比赛阶段报告的 F1 变化只能作为进一步检查的线索；评价本改动需要固定数据流、父模型和种子的对照。

## 3. B：真正从父模型续训，先处理小轴承组退步

默认候选为 `RSI_V2_B_EPOCHS=15`、`RSI_V2_B_LR=0.001`。
候选从本轮实际父 checkpoint 加载权重、归一化器和 Adam 状态，默认保留父模型随机种子；
`RSI_V2_SCRATCH_ARM=off`，从头训练不再进入默认比赛路径。
保留父模型始终是可选结果，生成训练候选不代表该候选必定上线。

目前公开数据上的 15 epoch 对照为：

| 指标 | 父模型 | 15 epoch 候选 | 整体变化 |
|---|---:|---:|---:|
| RMSE | 681.159833 | 663.636059 | 下降约 2.57% |
| MAE | 563.105841 | 559.431817 | 下降约 0.65% |

**这个整体结果不能作为直接部署依据。** `Bearing1_4` 只有 122 行，候选在该轴承上的
RMSE 上升约 **19.85%**、MAE 上升约 **33.92%**；`Bearing3_4` 占验证样本约 **90.23%**。
因此总体均值很容易掩盖小轴承组的明显退步。最终轴承分组保护应否决这个 15 epoch 候选并保留父模型，
不能把其整体均值下降宣传为 B 得分提升。

B 本轮的定位是减少无效计算、确保真实父模型继承关系，并阻止小组退步。
固定探索了 alpha=0.25、0.5 两个权重插值点，它们共享一次 15 epoch 续训的结果，不增加插值训练。
两点都未修复 Bearing1_4：MAE 分别仍上升约 4.88%、11.63%，因此均拒绝。
最终门控重新计算实际提交模型的预测，要求全局与每个至少有 10 个不同 snapshot 的轴承组 RMSE/MAE 不退步；
完全未知或没有足够支持的轴承分组时保留父模型，部分覆盖时明确记录限制。
本次默认 B 结果为保留父模型；不声称保住了此前从头训练模型的隐藏性能。

## 4. C：一次续训，采用更保守的权重变化

默认仅从本轮父模型续训一次：10 epoch、学习率 0.0003。
随后以同一个已训练候选生成参数插值模型：

`部署候选权重 = 父模型权重 + alpha × (续训候选权重 − 父模型权重)`

当前 `RSI_V2_C_MAX_ALPHA=0.25`，默认只评估 **alpha=0.25** 的保守更新。
显式设置 0.5 可用于有记录的对照探索；不应在看到隐藏测试结果后无约束地调参。
这是一个网络的参数更新，不是推理时运行两个网络的集成。
网络结构与输入归一化保持兼容。插值后的权重不再处于完整续训轨迹上，因此重置 Adam 的一、二阶矩与步数，
保留真实 epoch 历史，并在 checkpoint 中记录该处理；不能描述为插值后仍原样沿用旧 Adam 状态。

采用前须同时满足：

1. 全局 RMSE 相对父模型下降超过 0.3；全局 MAE、NASA 不上升，三项完整且有限。
2. 对有足够支持的 FD 子集检查 RMSE、MAE、NASA；默认支持要求为至少 8 行、2 台发动机。
3. 同时检查固定的 RUL 分组：0–99、100–249、250 及以上。可支持的分组不得在上述三项指标上退步。

这些检查在最终部署选择之前再次执行，覆盖模型网关改选和后续策略覆盖。
FD 识别不完整、组内支持不足或使用 RUL 备用分组时均记录覆盖范围。
**FD/RUL 分组不是平台隐藏漂移阶段的真实划分**，通过检查不能保证隐藏集或最差阶段一定改善。
FD 标识和验证 RUL 标签只用于评估，不作为模型输入，也不用于预测时分流。

## 5. 重复指标、保留父模型与缓存分别说明什么

报告显示的是某一轮最终选中产物的指标。如果连续选中同一个父模型，且验证数据、预处理和评估协议相同，
多轮出现完全相同的指标是正常现象；这既不能单独证明程序没执行，也不能证明每轮做了有效的新训练。
应联合检查父/候选 checkpoint SHA、训练内容摘要、实际候选、最终决策与资源记录。

旧 C 配置在生成并评估候选后才执行强制 retain，因此存在“完成训练后又丢弃候选”的计算浪费。
本候选已将显式 retain 判断提前：需要固定父模型时跳过不可部署的候选训练，仍执行公开测量、真实网关诊断、
历史引用、日志和提交协议，并记录 `fit_rows=0`。默认 C 已关闭强制 retain，由实际指标与分组检查决定是否采用更新。

训练缓存只复用**完全相同的训练计算**。键包含实际父 checkpoint 字节摘要、按原顺序排列的训练特征与标签、
训练配置、随机种子、训练源码和运行环境。不同后处理可以共享同一训练模型，验证指标则必须针对当前验证投影重新计算。
只看样本 ID 相同或分数重复，不能判断缓存可复用。

磁盘缓存默认最多 **8 条目 / 16 MiB**，每条包含 checkpoint 和 manifest 两个文件，最多占 **16 个状态文件**。
命中更新最近使用时间，按时间淘汰可核实的自有旧条目；单条超过预算则仅保存在内存。
未知文件、附带额外内容的目录及符号链接不删除、不跟随。预算覆盖缓存自有文件，不代表整个状态目录都已满足宿主限制。
SDK 的状态上传还存在 64 文件上限，宿主可以进一步设置字节限制。

每轮结构化记录写入原生状态中的 `round_records.jsonl`，与选择、父子 SHA、训练/验证内容摘要、模型调用和资源字段关联。
候选即使被拒绝，也保留缓存命中、实际训练动作、alpha 与分组检查结果，避免只看到最终父模型指标。
本地宿主此前未把已保存的状态目录传入下一轮，本轮已补齐；缓存跨轮复验要求日志累计轮数和实际命中同时成立。
这表示本地/平台状态中有可核对记录，**不表示已自动上传到 SwanLab**。

## 6. SDK、实际入口和构建身份

当前构建使用官方 SDK **1.0.5**。下载包 SHA-256 已核对为：

```text
bb5c616081de975d8f932a20cc00fd489e701e7585b69fdb52982bd669a305e6
```

该版本增加状态保存与轮次提交的请求、回执诊断日志；不能把 SDK 更新解释为评分算法变化。
平台可能直接执行 `python3 /app/harness.py`，因此 Python 入口会在导入 SDK/NumPy 前设置线程数默认值为 1，
而不是只依赖 shell entrypoint；用户或宿主显式指定的线程配置仍保留。

Dockerfile 和无 Docker 打包路径对齐默认环境，并在镜像中生成：

```text
/opt/zhixun/app/build-manifest.json
RSI_BUILD_MANIFEST=/opt/zhixun/app/build-manifest.json
```

来源清单记录版本、Git commit/dirty 状态、实际镜像代码与配置摘要、SDK 版本和包摘要，以及固定白名单中的非敏感配置。
不收集任意宿主环境变量，不写入模型服务或实验记录服务密钥。
Docker 构建需通过 `RSI_GIT_SHA`、`RSI_GIT_DIRTY` build args 提供提交身份；未提供则明确记录未知，不能编造 commit。
无 Docker 打包默认读取当前仓库身份。实际源码摘要独立保留，便于识别基于同一 commit 的未提交改动。

镜像校验会读取实际 Docker config ENV，而非假定宿主环境与镜像一致，并同时检查 shell dispatch 与直接 Python 入口。
本机合同测试与小型归档测试不等于已完成完整 Linux 镜像和真实宿主验收。

## 7. 训练、验证与资源证据边界

- 梯度训练仅使用当前平台允许的 `public/train` 投影，包括平台明确揭示并纳入训练投影的历史行；公开验证集只用于测量和选择。
- 父模型来自当前轮次提供的 checkpoint。默认不从头训练，不把验证标签并入 fit，不获取隐藏测试标签。
- FD/轴承/RUL 组检查是验证审计；分组标签或设备 ID 不得绕过正常模型输入边界。
- CPU 时间、墙钟时间、网关调用数和 Token 是不同口径；单机或替身宿主成本不能直接换算为平台资源效率分。
- 正式评测按官方当时发布的资源配置验证；试运行环境更大时，其耗时不能直接作为正式评测耗时承诺。
- 平台总分取决于隐藏流表现、各客观维度及材料评审。本文件只陈述已知代码行为与明确标注的公开实验结果。

### 当前源码的 C 资源对照

在同一 Python 3.12.14 / NumPy 1.26.4、六个线程变量均为 1 的 Mac 环境，
对完整 113,089 行训练、23,049 行验证数据串行运行三个单轮变体：

| 路径 | 参与者进程 CPU 秒 | 端到端秒 | 最终选择 |
|---|---:|---:|---|
| 上游 17cc307b，先训练后强制 retain | 36.934 | 37.7833 | 父模型 |
| 当前提前 retain | 2.361 | 2.9113 | 父模型 |
| 当前默认保守 C，alpha=0.25 | 3.306 | 3.8596 | 保守更新模型 |

当前默认 C 的本机进程 CPU 用时下降约 **91.05%**；提前 retain 下降约 **93.61%**。
这是完整路径单次对照，包含旧 SDK 1.0.4 与新 SDK 1.0.5 的差异，不能分解为某项改动的独立因果收益。
CPU 截至最终上传前，端到端还包含模拟器和 3 行预测检查；每条路径均为一次 fake gateway 调用。
每个变体使用新的 state，没有把跨轮缓存收益混入这次单轮比较。
没有测量正式环境的 2 核限额、真实模型服务费用或官方资源分，不能直接换算为比赛涨分。

## 9. 研究依据与适用范围

[Wortsman 等，ICML 2022，Model soups](https://proceedings.mlr.press/v162/wortsman22a.html)
展示了对同一预训练来源的兼容模型做权重平均、且保持单网络推理的思路。
本项目仅借鉴参数插值，不复现论文的多模型搜索流程；原论文主要针对大规模预训练模型，
不能据此断言当前小型 RUL 网络必然改善，实际采用依据是公开集上的逐组复测。

[Sagawa 等，ICLR 2020，Distributionally Robust Neural Networks for Group Shifts](https://arxiv.org/abs/1911.08731)
讨论了平均性能与最差组泛化之间的差别。本项目采用分组审计与上线否决条件，
并未实现该论文的 group DRO 训练目标，也不把组内样本数等同于独立设备数。
当前公开证据仍不能替代未参与选模的设备/时间外验证。

[官方 SDK 1.0.5 文档](https://rsi-index.115.zone/downloads/contest-harness-sdk-1.0.5.md)
约束父模型、公开训练投影和状态保存协议；评分中具体的增益与资源换算公式仍应以主办方正式规则为准。
