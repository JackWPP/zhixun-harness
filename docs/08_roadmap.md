## P1 · 高回报技术改进（预计 3 天）

按"预期收益 / 工作量"排序。

### P1-1 给 B 加滚动窗口特征（1 天）—— **单点收益最大**

**问题**：B 的输入是单帧 34 维快照，模型不知道"这个轴承已经跑了多久"、
"振动是在变好还是变坏"。这直接导致跨轴承泛化失败（比常数差 27%）。

**做法**：对每个轴承的时序，按时间顺序构造因果特征（**只能用 t 及以前**）：

| 特征 | 维度 | 作用 |
|---|---|---|
| 原始 34 维 | 34 | 现状 |
| 相对初始基线的比值 `x_t / x_0` | 34 | 归一化掉轴承间个体差异 |
| 过去 5/20 帧的均值、标准差 | 34×2×2 | 平滑与趋势 |
| 过去 20 帧线性斜率 | 34 | **退化速度**，最关键 |
| 累计最大值 / 当前值 | 34 | 相对劣化程度 |
| 已运行帧数（归一化） | 1 | 上下文，但注意不要泄漏寿命 |

**注意**：`已运行帧数` 会泄漏 RUL（RUL = N − i，知道 i 和 N 的关系≈知道 RUL）。
**安全做法**：只加 `当前值 / 累计最大值` 这类**尺度无关**的特征，
或者把 `i` 用训练集轴承的**中位寿命**归一化（而不是各自的 N）。

**预期**：B 的 RMSE 从 652 → **400 以下**（打进常数 536 以内是及格线）。
**这是把 B 从"负分"变"正分"的唯一路径。**

### P1-2 给 A 做无监督域适应（1–2 天）—— 唯一的病灶

**问题**：验证集 109 个乙醛样本，108 个被判成 Ethanol，且**所有容量、所有配方恒为 0**。
这是 batch-1 → batch-2 的域偏移，不是超参问题。

**做法**（按成本排序）：
1. **BN 统计量重估**（2 小时）：用验证集**特征**（不用标签）重算每层激活的均值方差。
   这是最便宜、最可能立刻见效的。
2. **CORAL / 均值方差对齐**（半天）：把 batch-2 特征的白化统计对齐到 batch-1。
3. **伪标签自训练**（1 天）：用当前模型给验证集打伪标签，高置信度的加入训练。
   **注意**：这用了验证集特征，属于 transductive 设定，
   必须在报告里声明"正式评测时不可用"或"仅用无标签特征"。

**预期**：乙醛 F1 从 0 → 0.3+ 就能让 macro-F1 涨 **0.05**（远超现在的 0.0126）。
**这是全项目性价比最高的一件事。**

### P1-3 加留出集，修掉选择偏差（半天）

从 `public/train.jsonl` 里按**单元**切 20% 做 holdout（不是按行！A 要按 batch、B 按轴承、C 按 unit）。
候选选择只用 holdout，验证集只在最后报告时用一次。

**这不会提升指标，但会让报告里的数字**从"乐观估计"变成"可信估计"。
评委更认这个。

### P1-4 门控阈值改成"2×种子噪声"（2 小时）

现在 `min_improvement = 0.0`，严格 `>0` 就接受，导致 C 第二轮 +0.0106 也过。
改成数据驱动的阈值：

| 任务 | 种子 sd | 建议阈值 |
|---|---|---|
| A（macro-F1） | 0.0029 | **0.006** |
| B（RMSE） | 4.719 | **9.4** |
| C（RMSE） | ~0.35 | **0.7** |

按这个阈值，**C 的第二轮增益会被正确拒绝**。这说明门控设计得更严格是**有据可依的**，
而不是拍脑袋。

### P1-5 种子集成（半天）

同一个配方跑 3–5 个种子，取预测平均（回归）或概率平均（分类）。
**这是最稳的免费提升**，通常能给 1–3%，而且不需要新方法。

## P2 · 把 harness 做成"真东西"（1–2 周）

### P2-1 从"6 个配方"改成"连续超参搜索"

当前动作空间是 6 个写死的点。改成：
- 连续空间：`lr ∈ [0.1×, 1.0×]`、`l2 ∈ [0, 0.01]`、`noise ∈ [0, 0.1]`、`epochs ∈ [3, 10]`
- 用 **TPE / 随机搜索 / 贝叶斯优化**，而不是 if/else
- 预算：每任务 20 次试验（当前 3 次）

**这是"方法设计 30 分"最直接的抓手**：从"查表"变成"搜索"，
而且可以画收敛曲线、画采样分布图。

### P2-2 诊断从"4 个阈值"改成"可学习的信号"

现在诊断全是魔法数字（0.5σ、0.08、1.3×、2 倍、0.5）。
改成：
- 用学习曲线形状（斜率、曲率、平台期长度）而不是单点阈值
- 用**病灶定位**：找出错误集中的样本、特征、类别对（A 的 Ethanol↔Acetaldehyde 混淆就是这么发现的）
- 输出**可执行建议**而不是文本模板

### P2-3 引入 LLM Agent（这才是赛题说的"自主改进"）

**现状**：完全无 LLM。**这是最大的"名不副实"风险，也是最大的机会。**

最小可行架构：
```
诊断报告(JSON) → LLM → 生成候选实验配置(JSON) → 沙箱执行 → 结果回灌 → 下一轮
```

关键设计：
- LLM **只生成配置和假设**，不碰代码（安全）
- 每次生成必须附带"预期结果 + 如何验证"，事后对照（这是赛题要的"依据结果决策"）
- 至少 3 次完整的"读历史 → 做实验 → 决策"记录（赛题硬性要求）
- 用 `harness/` 现有的门控和预算记账做护栏（这是已有的、真实的价值）

**这才是能回答"你们是不是 RSI"的东西。**
