## 0. 一页纸摘要（可直接做封面/摘要页）

**一句话**：我们没有去"训一个更准的模型"，而是造了一台**能在运行中自己发现漂移、自己提出假设、自己跑实验、再被确定性门控管住**的受控 RSI（Recursive Self-Improvement）机器——让工业模型在无人干预下持续自我改进，且全过程可复现、可审计、可回滚。

**四个核心事实**：

| 维度 | 事实 | 数字 |
|---|---|---|
| 性能 | 严格官方口径 3 任务 × 10 轮（确定性路径） | A macro-F1 **+4.5%**、B RMSE **−39.6%**、C RMSE **−9.4%**（相对门控集基线）；全验证集独立推理 B **−38.0%**、C **−4.5%**、A **+0.8%** |
| 漂移适应 | A 外部 UCI 批次流（隐藏批，仅验证） | frozen **0.2774 → 0.7866**（full 门控，约 2.8 倍）；Track X 4 批部署模型均值 **0.4783 vs frozen 0.2759（+73%）** |
| 自主性 | 真实 LLM kernel 无人干预运行 | A 3 轮 **0.7032 → 0.7207**、B 2 轮 **678.022 → 602.239**；跨 run 首轮工具调用 **18 → 13** |
| 工程 | 资源与可复现 | 3×10 轮全程 **30 分 25 秒 / 56 个实验 / 0 LLM token**；两次独立运行指标**逐位一致**；镜像 **376MB**、CPU-only、离线 |

**三个差异化**：**受控**（无 shell/网络/文件，白名单 + 区间 + 门控 + 预算 + 全审计）、**可复现**（逐位一致、sha 链、独立 predict 复算）、**可迁移**（task.json 契约，未知任务 D 零代码 4 批 0 错误）。

**交付物**：Harness 镜像（docker save tar，linux/amd64）+ 模型配置（checkpoint + postprocess + 父子 sha 链）+ 实验记录（JSONL/SQLite/summary + workspace_report，可导 SwanLab）+ 零依赖看板 + 26 篇文档 + workspace v2 平台适配（describe/train/predict）。

# 第一部分 背景

## 1.1 赛题到底在要什么

官方赛题的落点不是"调参打榜"，而是：

> 构建一个**工业模型自进化系统**：在有限的学习与标注预算下，让模型在公开数据上**自动维持并提升**性能，把**受控的递归自我改进（RSI）**落到真实工业场景，并给出**可核验的过程记录**。

这句话里有三个关键词，决定了整个技术路线：

1. **工业场景**：数据不是静态数据集，而是持续到达、持续漂移的流；标签有限且滞后；设备不能停、不能联网、不能上 GPU。
2. **自动维持并提升**：不是训练一次就结束，而是"上线后还能自己变好"；既要提升，也要在变差时稳住（最差阶段/恢复速度是评分项）。
3. **受控 + 可核验**：允许模型自进化，但必须能说清"改了什么、为什么改、谁批准的、效果如何"，并留下可复现的记录。

赛题给两条路线二选一：**平台模型 Harness 工具+技能组合**，或**传统微调**。我们选择前者——因为"自进化能力"的本质不是权重更新，而是**决策过程**；把决策过程做成可执行、可审计的闭环，才是 RSI 的落点。同时我们保留了传统微调的合法部分（官方 baseline 的同结构续训），两者是"策略层自主 + 模型层受控小步改进"的组合。

## 1.2 三个工业任务：三类真实的"坏情况"

赛题提供三个数据集、每任务一个官方基线 checkpoint。它们不是三份普通数据，而是三种典型的工业困境：

| | 任务 A | 任务 B | 任务 C |
|---|---|---|---|
| 数据 | UCI Gas Sensor Array Drift（#224） | XJTU-SY 轴承全寿命 | NASA C-MAPSS（FD001–FD004） |
| 输入 | 128 维气体传感器阵列 | 34 维（17 特征 × 2 通道振动） | 24 维（3 操作设置 + 21 传感器） |
| 任务 | 6 类气体分类 | 轴承剩余寿命 RUL（分钟） | 发动机剩余寿命 RUL（cycles） |
| 指标 | macro-F1 ↑ | RMSE ↓ | RMSE ↓ |
| 官方基线 | 0.714030 | 681.160 | 52.869 |
| 公开数据 | train 445 行（仅 batch1） / val 1244 行（仅 batch2） | train 7032 行 / 9 轴承；val 1679 行 / 3 轴承 | train 113089 行 / 182 台；val 23049 行 / 62 台 |
| 数据陷阱 | 训练/验证跨数月**时间漂移**；乙醛类跨批 F1 恒 0；Toluene 验证仅 5 条 | 有效样本量只有 **9 个轴承**；验证 90.2% 来自单个轴承；**基线 RMSE 681 比常数预测 536 还差 27%** | 验证集是**同分布随机切分**（标准化后 \|z\|max 3.0，对比 A 的 299.6），几乎没有漂移对象 |
| RSI 该做什么 | 适应跨批漂移、补不可迁移类 | 先诊断"基线本身失效"，再修复 | 识别"没有漂移"，**不要乱改**，守住不退步 |

**这张表就是整套系统的方法论起点**：三个任务分别对应 RSI 的三种正确行为——**该适应时适应（A）、该修复时修复（B）、不该动时不动（C）**。"受控"不是保守，而是**按证据行动**。

补充：三个数据包结构完全同构（TASK.md / START.md / TRAINING_GUIDE.md / training.json / baseline-info.json / checkpoint.npz / public split / baselines 代码与测试），基线是 NumPy 手写小 MLP + Adam（A 4326 参数、B 865、C 833），checkpoint 保存全部续训状态（参数、Adam 一/二阶矩、steps、归一化与目标缩放），因此**续训与从头训练数学等价、基线分数可逐位复算**——这是"可核验"的工程基础，也是我们所有实验可比性的前提。

## 1.3 赛题在考什么：评分结构说了算

| 部分 | 分值 | 细分 |
|---|---|---|
| 客观分 | 35 | 平均性能提升 15、最差阶段与恢复速度 10、稳定性 5、资源效率 5 |
| 专家分 | 65 | 方法设计 30、实验分析 15、安全与工业落地 10、报告与答辩 10 |
| 加分 | ≤10 | 扩展数据验证、记忆与技能、技术创新等 |

**战略判断（重要）**：客观分里"平均提升"只有 15 分，而专家分中"方法设计 30 + 实验分析 15"合计 45 分，接近总分一半。**卷 0.01 的指标收益极低，卷"方法论 + 可核验的实验记录"才是主战场。**所以我们的目标函数是：

> 性能稳定优于基线（拿到客观分的基本盘） × 过程可解释可复现（拿专家分的大头） × 工程可交付（拿落地分与答辩分）。

这也是为什么本报告第二部分 (a) 的篇幅大于 (b)——**方法本身就是作品**。

## 1.4 硬性约束（也是设计输入）

- **无人干预**：一条命令跑完，不能有人中途选模型、调参数。
- **过程记录**：至少 3 次完整的"读历史 → 做实验 → 依据结果决策"记录。
- **不低于基线**：否则出局（所以门控的第一目标是"不退化"，其次才是提升）。
- **材料齐全可复现**：镜像 + 源码 + 模型调用信息 + 实验记录链接 + 设计说明 + 技术报告 ≤10 页 + 演示视频 ≤5min + 来源声明。
- **数据纪律**：只用平台允许数据，不得获取隐藏标签。
- **次数纪律**：每队试运行 ≤10 次（累计），正式评测 ≤2 次；这决定了**不确定性必须先在本地消化**——我们的私有模拟协议（private-sim）就是为此建的。
- **算力纪律**：统一离线环境、4 核 8G、无 GPU、禁外网、整 run 6 小时、40 实验/任务、2M token/任务。

# 第二部分 重点内容

## 2(a) 我们是如何实现的

### 2(a)-1 系统总览：一句话 + 一张图

**一句话**：LLM Agent 驱动的**受控 RSI harness**——在离线 Docker 内，对官方工业 checkpoint 自动完成「漂移监测 → 诊断归因 → 实验设计 → 沙箱执行 → 统计门控 → 记录归档」的闭环；模型始终是官方 baseline 的同结构续训产物，改进只发生在**参数小步优化 + 推理期校准 + 策略选择**上。

```
平台 SDK（contest.harness.workspace.v2：describe / train / predict）
        │  每轮 train(rnd)＋逐行 predict(sample, model_dir)
┌───────▼──────────────────────────────────────────────────────────┐
│ rsi/platform/submission.py   平台适配层（候选评估 + 门控 + 提交）  │
├──────────────────────────────────────────────────────────────────┤
│ rsi/runner.py                runner（3 任务 × 10 轮：预算/状态/报告）│
│   ├─ 双控制器：kernel（LLM 自主决策） / pipeline（确定性六步兜底）   │
│   ├─ rsi/agent/               supervisor · kernel · Guard · GoalLoop │
│   ├─ rsi/drift.py             漂移统计 + 归因 + 严重度 + 推荐动作     │
│   ├─ rsi/strategies.py        白名单策略（retain / 续训 / ridge / SWA / recenter / shrink）│
│   ├─ rsi/executor.py+worker.py 参数二次校验 + 子进程沙箱 + 超时       │
│   ├─ rsi/selection.py         统计门控（promote / retain / rollback） │
│   ├─ rsi/memory/ + skills/ + knowledge/  记忆 · 技能 · 离线知识库     │
│   └─ rsi/records.py           JSONL / SQLite / summary / workspace_report │
└───────┬──────────────────────────────────────────────────────────┘
        │ 受限工具调用（只读状态、提交实验/决策）
   LLM（OpenAI 兼容端点；比赛环境切换 PyTRiO 只需改环境变量）
   交付形态：Docker 单镜像（linux/amd64，约 376MB，离线、CPU-only）
```

**一图流的一句话讲法**：左边是工业系统（只给数据和 checkpoint），右边是平台（只收模型和记录），中间这台机器自己完成"诊断—实验—验证—上线—沉淀"。人只在一开始按下启动键。

### 2(a)-3 总体架构：五层 + 两个控制器

**五层职责**：

| 层 | 关键模块 | 职责 |
|---|---|---|
| 数据层 | tasks / splits / data | 三任务定义；验证集切三层互斥子集；UCI 外部探针只验证不训练 |
| 决策层 | agent/kernel、coordinator、delegate、guard、goals | kernel 自主主循环、6 角色协作、Guard 边界、GoalLoop 收口；pipeline 确定性兜底 |
| 执行层 | strategies / executor / worker / selection / inference | 白名单策略、二次校验 + 独立子进程、统计门控、推理期校准 |
| 记忆层 | memory / skills / knowledge | 有界工作记忆与长期记忆、SKILL.md 渐进披露、SQLite 经验库、12 篇知识库 |
| 记录层 | records / state / dashboard | JSONL 审计真源、状态快照、summary 与 workspace_report、证据抽屉看板 |

**一轮 RSI 的时序（9 步，PPT 可画成流程条）**：

1. **切分**：从官方 validation 切出 calibration / selection / report 三个**互斥**子集（manifest 记 sha），A 另设外部 UCI 探针（只报告）。
2. **父模型评估**：在所有子集上评估当前父 checkpoint，得到本轮比较基准。
3. **漂移窗口**：按任务取累计窗口（A 有跨批漂移、B 按轴承单元、C 无时间窗口），计算漂移统计。
4. **诊断归因**：均值/方差偏移、KS、相关性、标签分布 JS、窗口性能跌幅 → 漂移类型、严重度、归因 top 特征、推荐动作。
5. **实验设计**：生成 1–3 个可检验假设与候选实验（策略 + 参数区间）。
6. **评审**：Critic 审查假设与候选；边界情况触发 Arbiter（只能更保守）。
7. **沙箱执行**：worker 子进程跑候选，产出新 checkpoint 或后处理参数 + 三个子集指标；失败只留 log_tail，不终止 run。
8. **统计门控**：selection 集上"提升 ≥ margin 才 promote 新 checkpoint、劣化 ≥ 2×margin 自动 rollback、否则 retain 父模型"；**最终交付的是历史最优，不是最后一轮**。
9. **记录与沉淀**：写 rounds.jsonl（假设/变更/指标/父子 sha/用量/trace），更新记忆与技能，MemoryReviewer 提炼 lesson。

**两个控制器**（这是"既能自主、又能保底"的关键）：

- **kernel（自主）**：LLM 在受限动作空间内自己决定下一步（读历史→假设→实验→评估→决策→记忆），代码实测 **19 个受限工具**。
- **pipeline（确定性）**：固定六步流程，不依赖 LLM。
- `--controller auto`：LLM 可用走 kernel；连续 2 轮失败自动降级 pipeline 并在记录中标记 fallback。**保证在封闭评测环境里一定产出合规的 10 轮结果。**

### 2(a)-4 让系统"具备 RSI 能力"的关键机制

**① 诊断先于行动（drift.py）**
每轮先生成漂移报告：均值/方差偏移、KS 统计、特征相关性变化、标签分布 JS 散度、窗口性能跌幅，输出漂移类型（P(X)/P(Y)/P(Y|X)）、severity、causes、top 特征、recommended_actions 与知识库提示。**没有诊断，就没有"该不该改"的依据**——这是 RSI 与"无脑调参"的分界线。

**② 受限动作空间**
候选只能来自白名单策略（retain / 同结构续训 / ridge_last_layer / SWA / recenter / shrink 等）与参数区间；不改网络结构、输入维度、归一化与目标缩放；promote 必须重新通过门控计算。LLM 可以"更保守"，但不能"更激进"。

**③ 沙箱执行**
执行器对 LLM 提交的每个参数做**二次校验**（区间、类型、白名单），再放进独立子进程运行，带超时、CPU/实验数记账；候选失败只回传 log_tail，主流程继续。**LLM 的意图被执行器翻译成受限动作，不可能越权。**

**④ 统计门控（selection.py）**
门控阈值 = **2 倍种子噪声**（A 0.004 / B 5.0 / C 0.3）：selection 集提升 ≥ margin 才 promote；劣化 ≥ 2×margin 自动 rollback；否则 retain 父模型。门控保证最终交付的是**历史最优**，而不是"最后一轮碰巧好的"。

**⑤ 三层记忆 + 技能（memory / skills）**
- 工作记忆：每轮 brief 的冻结快照（任务、父指标、预算、最近 5 轮、漂移、策略胜率、技能索引）；
- 长期记忆：`MEMORY.md`（4000 字符）+ 分任务 `TASK_<A|B|C>.md`（2000 字符），有界、去重、跨 run 复用；
- 经验索引：SQLite（WAL+FTS5）的 rounds/experiments/lessons/strategy_stats，JSONL 为审计真源、可重建；
- 技能：`skills/<name>/SKILL.md`，索引进 brief、正文按需 `read_skill` 渐进披露（种子技能 6 个）。
- 实测：**跨 run 首轮工具调用 18 → 13，input tokens 110,219 → 107,823**；记忆被外部篡改时拒绝覆盖并留 `.bak` 备份，越权指令/代码围栏/危险命令一律拒绝并记审计。

**⑥ 离线知识库（12 篇）**
评测环境禁外网，Agent 不能上网查资料。我们一次性策展 12 篇漂移/校准/实验设计/合规文档（漂移类型学、KS/PSI/MMD/Page-Hinkley、特征归因、recenter/shrink、RUL 校准、续训与迁移、实验证伪、SwanLab 记录等），FTS5 索引，brief 注入 ≤1.8K 字符 + `search_knowledge` 按需检索，引用写 `[K#]`。**知识只扩大"分析思路"，不扩大"操作权限"**：Guard 不因检索到某方法就允许 propose。

**⑦ 确定性兜底（降级阶梯）**
LLM 不可用/超时 → 确定性 planner；忘记 decide → supervisor 用 best_candidate + selection.gate 自动收口；无实验无决策 → 本轮失败回退 pipeline；token 到 92% → tripwire 收口；数据库损坏 → 用 JSONL 重建。**任何单次失败都不终止整个 run**——这是"无人干预"的工程底线。

**⑧ 全链路审计与可复现**
每轮记录：假设、变更摘要、候选指标（cal/selection/report/外部探针）、父子 checkpoint sha256、实验耗时与 CPU、LLM 调用与 token 用量、Guard 审计、Agent trace；checkpoint 采用固定 zip 时间戳，**同样权重产生同样字节**，父子 sha 可逐级追溯；看板提供"证据抽屉"。两次独立 strict 运行指标**逐位一致**。

### 2(a)-5 我们对 RSI 的理解（核心页）

**定义（我们的版本）**：

> **受控递归自我改进 = 在固定目标与固定行动空间内，让系统自主完成"观察 → 假设 → 实验 → 评估 → 决策 → 记忆"，并让改进能力跨轮、跨运行复利。**

它由三层构成，缺一层都只是"调参自动化"：

| 层 | 改进对象 | 我们的手段 | 证据 | 风险控制 |
|---|---|---|---|---|
| **L0 模型层** | 当前模型在漂移数据上的表现 | 官方 baseline 同结构续训（小步、可回滚）+ 推理期校准（recenter / shrink / damage_shrink / 两阶段续训） | A 门控集 +4.5%；B −39.6%；C −9.4%；A 外部 hidden 0.2774→0.7866 | 不改结构/归一化/格式；父子 sha 链；promote 必须过门控 |
| **L1 策略层** | "怎么改"的决策策略 | LLM Agent 在 19 个受限工具内自主观察/假设/实验/决策；pipeline 确定性兜底 | kernel A 0.7032→0.7207、B 678.022→602.239，全程无人工 | Guard 工具边界 + 执行器二次校验 + Arbiter 只能更保守 |
| **L2 经验层** | 经验本身（记忆/技能/知识） | 三层记忆、SKILL.md、SQLite 胜率、12 篇知识库、跨 run 复用 | 跨 run 首轮工具调用 18→13；知识引用进入决策 | 注入扫描；记忆是数据不是指令；有界去重 |

**与相邻概念的边界（答辩高频问题）**：

| | 传统微调 | AutoML / HPO | 自由自进化 Agent | **我们的受控 RSI** |
|---|---|---|---|---|
| 改什么 | 权重 | 超参/结构 | 任意代码 | 策略选择 + 参数小步 + 推理期校准 |
| 谁决策 | 人 | 搜索器 | LLM（无约束） | LLM 提议，**确定性系统验证/否决** |
| 漂移处理 | 不处理 | 不处理 | 不确定 | 诊断驱动，按证据适应或保持 |
| 安全边界 | 人工评审 | 预算 | 弱 | 无 shell/网络/文件 + 白名单 + 门控 + 预算 |
| 可复现 | 一般 | 一般 | 差 | **逐位可复现**（固定 seed、确定性门控、sha 链） |
| 经验沉淀 | 无 | 无 | 有但不稳定 | 三层记忆 + 技能 + 知识库，有审计 |

**一句话总结我们的 RSI 观**：

> **改进的对象不是代码，而是"改进过程"本身。LLM 负责提出假设与做出选择，确定性系统负责验证与否决；每一次"改"都必须有诊断依据、有实验证据、有回滚路径、有记录可查。**

**为什么工业场景必须是"受控"的**：工业模型一旦上线，错误是有成本的——乱改结构会破坏可维护性，乱用数据会违反合规，乱采纳候选会在最差阶段掉点。所以 RSI 的"自我改进"必须以**可解释、可回滚、可审计、预算硬约束**为前提。我们的 8 个关键机制，本质上都是"给自进化装上刹车和黑匣子"。

### 2(a)-6 我们的迭代方法论（"我们自己也在做 RSI"）

这套系统不是一次写成的，它的演进史本身就是一次宏观的"读历史 → 实验 → 决策"：

| 版本 | 关键动作 | 为什么 |
|---|---|---|
| v0.1 | 旧原型审计 | 发现确定性策略路由器+受控续训器**并非 Agent/RSI**：6 条硬编码配方、lr 恒为父模型 ×0.3、策略小模型从未被调用、验证集既选又报 → 决定重写 |
| v0.3 | 确定性六步 pipeline + 三层互斥切分 | 先让"方法正确"，再谈自主 |
| v0.4 | LLM kernel（6 角色）+ 沙箱执行 + 统计门控 | 让系统"自己决策"，但决策必须被执行器/门控兜住 |
| v0.5.1 | strict canonical 3×10 逐位复现 | 锁定可复现的官方口径基线结果 |
| v0.6 | 批次流协议 + 离线知识库 + 记忆三层 | 让 RSI 能处理"持续到达的数据流"，并让经验可复利 |
| v0.7 | A 类历史适应（history-adapt） | 用已揭示历史标签做校准，提升跨批适应 |
| v0.8 | **私有模拟协议（private-sim）** | 发现旧协议把"当前批验证标签"泄漏进选型 → **主动作废旧数字**、重做诚实批次协议；这是"自我批判"能力的最好证据 |
| v0.9 | workspace v2 平台适配（describe/train/predict） | 对齐官方评测入口，从"本地 harness"变成"可提交系统" |

其中 v0.8 的"作废旧数字"值得单独讲：**一个声称能自我改进的系统，首先必须敢于否定自己的成绩。**我们为此建了 E0 不变性测试（打乱答案后 decision.json/predictions.jsonl 逐字节相同），并明确"hidden 批永不揭示"的边界。这正好回应赛题"可核验过程记录"的要求。

## 2(b) 性能指标的提升与优势如何体现

### 2(b)-1 先讲清楚评测口径（可信度的前提）

我们不用"整体验证集既选模型又报分数"的常见做法，而是把官方 validation **切成三个互斥子集**：

| 子集 | 用途 | 是否参与选型 |
|---|---|---|
| calibration | 推理期校准参数拟合 | 仅用于校准类策略，不参与选型 |
| selection | 门控（promote / rollback） | **只用于选型** |
| report | 只报告 | **绝不参与选型** |
| A 外部 UCI 探针 | 漂移泛化观察 | 只报告，不训练、不选型 |

门控阈值 = **2 倍种子噪声**（A 0.004 / B 5.0 / C 0.3），固定 seed=42（关键实验另跑 seed=43 交叉验证）。官方基线分数可逐位复算（A 0.7140297221 / B 681.1598326043 / C 52.8685725661），我们的结果两次独立运行逐位一致。**这是"我们的提升不是噪声"的第一层证据。**

### 2(b)-2 主结果：严格官方口径（3 任务 × 10 轮）

以下为 v0.5.1/v0.6 canonical strict 运行（`RSI_ALLOW_EXTENDED_DATA=0`，只用官方 train；确定性 planner；`run .scratch/rsi-v052/rsi-20261115-210157`）：

| 任务 | 指标 | 官方基线 | 我们（selection 门控集，基线→最终） | 相对变化 | report 留出集（只报告） | 全验证集独立推理 |
|---|---|---|---|---|---|---|
| A | macro-F1 ↑ | 0.714030 | 0.703220 → **0.734555** | **+4.46%** | 0.686380 → 0.683406（−0.43%） | 0.71987（vs 0.714030，**+0.82%**） |
| B | RMSE ↓ | 681.160 | 678.022 → **409.737** | **−39.57%** | 664.009 → 424.130（−36.13%） | 422.24（**−38.01%**） |
| C | RMSE ↓ | 52.869 | 44.749 → **40.524** | **−9.44%** | 57.460 → 56.021（−2.50%） | 50.47（**−4.54%**） |

> 注意口径：表中「相对变化」以 **selection 子集上的基线**为分母（A 0.703220 / B 678.022 / C 44.749），不是官方整体基线 0.714030 / 681.160 / 52.869——因为门控在 selection 子集上进行，只有同子集对比才公平。官方整体基线对应的是最后一列「全验证集独立推理」。

**读表要点（PPT 讲法）**：

- **B 是最大收益**：门控集 −39.6%，独立全验证集 −38.0%，两次口径互相印证。
- **C 是小幅但稳定的收益**：−9.4%（门控集）/ −4.5%（全验证集），且 10 轮里 9 轮 retain（只采纳初始一次两阶段续训）——**没有为了刷分反复折腾**。
- **A 要诚实分层看**：门控集 +4.5%、全验证集 +0.8%，但静态 report 留出集 −0.43%。按全验证集口径 A 为 +0.82%，高于门控 margin 0.004，"不低于基线"成立；report 子集的 −0.43% 必须同时披露。原因很清楚：A 的验证集只有**一个批次**，静态场景里没有"跨批漂移"可供适应；A 的收益主要体现在**批次流场景**（见下表）。我们不把它包装成"全面大幅提升"，而是按场景分开报。
- 资源：整轮 3×10 wall **30 分 25 秒**、CPU **1059 秒**、**56 个实验**、**0 LLM token**（确定性路径）；远低于 6h / 36000s CPU / 40 实验/任务 / 2M token 的预算。

### 2(b)-3 漂移场景：RSI 真正兑现价值的地方

静态验证集只能证明"不比基线差"，**批次流才能证明"会自己变好"**。以下全部为只验证不训练的诚实协议（当前批标签在预测后才揭示，隐藏批永不揭示）：

| 场景 | 对照 | 结果 | 说明 |
|---|---|---|---|
| A 官方 validation 顺序 8 批重放 | frozen（不改进） → pair（历史标签校准） | 0.6158 → **0.6571（+6.7%）** | 严格官方数据、无外部数据 |
| A 外部 UCI 批次流 b3–b10（hidden b8–b10 均值） | frozen / adapt / full 门控 | 0.2774 → **0.7578** → **0.7866** | 约 **2.8 倍**；full 门控 5 批中采纳 4 批 |
| A Track X 四批（batch6–9，部署模型 vs frozen vs oracle） | 0.3209 / 0.3395 / 0.2563 / 0.1868 | **0.4697 / 0.4871 / 0.4053 / 0.5511** | 四批均值 **+73%**；oracle 0.95–0.99（给上限参照） |
| A 全量批次流彩排（UCI b1–b10，2 seed） | frozen .4862 / pair .5276 / recenter .5589 / adapt .7385/.7625 / full **.7653/.7684** | **+57.7%**（full 均值 .7668） | 与 private-sim 外部结论一致；标签减半仍 0.7199、20 批长流 0.8221 |
| B 全量批次流彩排（arrival 批均值，2 seed） | frozen 650.02 / recenter 572.65 / adapt **435.56/432.40** / full 497.01/502.01 | **−33.2%** | full 因 selection 噪声反而更差；隐藏段证据混合，路由标"待验证" |
| C 全量批次流彩排（arrival 批均值，2 seed） | frozen **50.37** / recenter 50.94 / adapt 51.08/51.03 | **frozen 最优** | 系统识别"无漂移、不该改"，选择 retain；full 未跑（成本高） |
| B/C 隐藏段（private-sim 最后 2 批） | B frozen 357.47 vs adapt 446.96；C frozen 56.29 vs adapt 58.68 | 混合：B 的 hidden 段不支持 adapt、C 支持 frozen | **如实报告，不选择性展示**，因此 B 路由标"待验证"、C 路由 frozen |

**由此得到的路由策略（auto）**：A official → pair；A external → full；B → adapt（标注待验证）；C → frozen；未知任务 → 默认保守策略。

全量彩排的完整协议、逐 lane 结果与问题清单已写入 docs/27_FULL_SIMULATION.md 与 docs/12_EXPERIMENTS.md §12.25（L1 协议级 24 lanes + L2 workspace-v2 真实入口每任务 10 轮 PASS；L3 kernel 彩排进行中，B/C 记录缺失，**不可作为结果引用**）。**它们仍属开发期证据：未提交、未复验、未 trial，PPT 上如需引用请标注「开发期彩排」**，不要与 strict 官方口径混排。

**这里有三层"能力"证据**：

1. **会适应**：A 外部流 frozen 0.28 → 门控后 0.79，且缺类/传感器扰动/长流下几乎不衰减（缺 Acetaldehyde 仍有 0.7495，两轮长流 0.7631）；
2. **会识别不该适应**：C 上 frozen 最优，系统不折腾；
3. **会承认不确定**：B 的隐藏段证据混合，就明确标注"待验证"而不是硬吹。

### 2(b)-4 自主性证据：真实 LLM kernel 的无人干预运行

以下为**真实 LLM 驱动 kernel**（不是确定性 planner）的 strict 运行：

| 运行 | 轮数 | 结果 | 过程指标 |
|---|---|---|---|
| A kernel（strict） | 3 轮 | 0.7032 → **0.7207**（+2.5%） | 20/15/14 工具调用；1 次 Panel（4 角色）；知识库检索 1 次/3 hits；440,715 tokens；wall 1443s |
| B kernel（strict） | 2 轮 | 678.022 → **602.239**（−11.2%） | 5 个实验；467,689 tokens；3 次 LLM 调用；wall 939.4s |
| A 架构验证轮（早期，数字作废，仅作架构证据） | 3 轮 | 0.7032 → 0.9373 | 18/14/14 调用；361K tokens；wall 694s |
| 未知任务 D（task.json 契约） | 4 批 | 零代码改动，0 errors | 证明运行时与任务解耦 |

**特别说明**：A 架构验证轮用了 calibration 数据，违反严格口径，因此 **0.9373 这个数字我们主动作废、不在任何正式材料中引用**，只作为"Agent 自主闭环可跑通"的早期证据。B kernel 的差距也主动披露：**没有发现 `damage_shrink` 这个强配方**（候选清单/知识注入仍需补强），所以 B 的正式成绩来自确定性路径，而非 LLM 路径。

### 2(b)-5 优势是如何"体现"出来的：六个维度

1. **平均提升（客观分 15）**：B −39.6%、C −9.4% 直接兑现；A 在业务真实的漂移场景 +6.7% ~ 2.8 倍，并以"场景分口径"呈现，而不是混在一起。
2. **最差阶段与恢复（客观分 10）**：门控 + rollback + Panel 提供"最差阶段保护"。三个 strict 运行都呈现同一个行为——**采纳一次后就连续拒绝噪声**：A 在 r1/r2 用 recenter 连续 promote 到 0.7346，其后 r3–r10 全部回滚（候选未过 2×margin/gate），最终始终保留历史最优 0.7346；B 在 r1 采纳 damage_shrink 到 409.7 后连续 9 轮 retain；C 在 r1 采纳两阶段续训到 40.52 后连续 9 轮 retain。门控的语义是"没把握就不动"，这正是最差阶段/恢复分数的机制来源。
3. **稳定性（客观分 5）**：两次独立 strict 运行指标**逐位一致**；E0 不变性测试（打乱答案后决策逐字节相同）通过；门控阈值 = 2×种子噪声，把随机波动挡在门外。
4. **资源效率（客观分 5）**：3×10 轮 30 分钟 / 56 实验 / 0 token（确定性路径）；kernel 3 轮约 24 分钟 / 44 万 tokens（平台预算 800 万）；A 的最大收益来自**零 checkpoint 字节的推理期 recenter**（不训练、秒级、不改模型）；镜像 376MB，CPU-only、离线。
5. **可复现与可验证**：官方基线可逐位复算；我们的 run 可回放；独立 predict 在全验证集复算与报告值一致（A 0.71987 / B 422.24 / C 50.47）；父子 sha 链 + JSONL 审计 + 看板证据抽屉。**答辩时任何数字都能当场翻到对应 run 的轮次记录。**
6. **方法论与可迁移性（专家分 45 的主战场）**：受控 RSI 三层框架 + 诚实评测协议（三层切分 / 批次协议 / E0 / 外部测试床）+ 工程化交付（workspace v2 适配 / 一键镜像）。未知任务 D 零代码跑通，证明它不只是"三任务特调脚本"，而是一个**通用 RSI 运行时**。

### 2(b)-6 诚实的边界（这一页反而最能拿"实验分析"分）

| 边界 | 事实 | 我们的处理 |
|---|---|---|
| A 静态 report 留出集略降 | 0.6864 → 0.6834（−0.43%） | 按场景分层报告；静态单批没有可适应的漂移，收益在批次流；不掩饰 |
| A 验证集统计功效弱 | 单批次 batch2；Toluene 仅 5 条（macro-F1 量化步长约 0.008） | 用外部 UCI 多批测试床补足证据；报告中注明方差 |
| B 基线本身失效 | 官方基线 RMSE 681 > 常数预测 536（差 27%） | 明确"提升的一部分是修复坏基线"；hidden 段证据混合，路由标"待验证" |
| B 行级切分泄漏 | 验证 90.2% 行来自单个轴承，行级切分无法完全消除轴承内泄漏 | 已用 LOBO（留一轴承）做保守复算并在文档披露 |
| C 无漂移对象 | 验证集同分布随机切分 | 系统识别后选择 retain（frozen 最优），不强行"改进" |
| 正式评测未开放 | 平台 blocker，无 PyTRiO Key，未做官方试运行 | 用 workspace v2 fake-host + 全量彩排做端到端演练；如实说明"未试运行" |
| kernel 强配方缺失 | kernel 路径未发现 damage_shrink；A kernel 3 轮提升小于确定性路径 | 主动披露；后续把强配方显式加入候选清单与知识注入 |
| 记忆的指标级收益未确认 | memory on/off 两次 strict 运行指标逐位一致（仅 wall +71.6s）；跨 run 省探索 18→13 是行为层证据 | 如实标注"指标无增益、探索成本下降"，不写成因果结论 |
| 镜像可再裁剪 | 376MB 中部分依赖可剥离 | 列入工程优化清单 |

**一句话**：我们宁可少报一个数字，也不让评委在细节上抓到问题——**诚实本身就是"实验分析"能力的一部分**。

# 第三部分 总结与展望

## 3.1 总结：四句话

1. **做成了什么**：一套可运行的受控 RSI harness——LLM Agent 在离线 Docker 内，对官方工业 checkpoint 自动完成"诊断→假设→实验→门控→记录→沉淀"闭环，支持确定性兜底与平台 v2 接口。
2. **方法上贡献了什么**：把 RSI 落成**三层框架**（模型层小步可回滚改进 / 策略层 LLM 受限自主决策 / 经验层记忆与技能复利），并用 **Guard + 统计门控 + 降级阶梯 + 全审计** 四重机制保证"受控"。
3. **性能上做到了什么**：严格官方口径 A +4.5%、B −39.6%、C −9.4%；A 漂移场景 frozen 0.28 → 0.79（约 2.8 倍）；3×10 轮 30 分钟、0 token、逐位可复现。
4. **工程上交付了什么**：376MB 离线镜像、模型配置与父子 sha 链、实验记录与看板、26 篇文档、workspace v2 适配、提交包——材料齐全、可复现、可现场演示。

## 3.2 方法论沉淀（可迁移到更多工业场景）

- **受控 RSI 三原则**：行动空间受控（白名单+区间+二次校验）、决策可验证（统计门控+回滚+审计）、经验可复利（记忆/技能/知识库）。
- **诚实评测协议**：三层互斥切分 + 批次协议（当前批标签预测后才揭示）+ E0 不变性 + 外部测试床只验证不训练。这套协议可以直接复用到任何"数据持续到达 + 标签滞后"的工业任务。
- **工程交付范式**：一个镜像 + 一个 task.json 契约 + 一套 workspace v2 适配 + 一套审计记录，即可把 RSI 运行时搬到新模型/新产线。

## 3.3 展望

**（1）赛题层面 —— 接下来要做的事**

- 平台开放试运行后：按 ≤10 次 trial 预算做"trial → select"（先小步验证真实平台指标，再决定正式提交）。
- 用 workspace_report 的十轮判分口径复核 A/C 的 draft 状态，避免"基线未转正"带来的评分口径风险。
- 答辩准备：用看板现场回放三轮证据（主表、漂移场景、kernel 轨迹），三个核心数字 + 三个洞察（受控、诚实、可迁移）。

**（2）系统层面 —— 明确的工程路线图**

- **B**：用滚动窗口/上下文特征替代当前 damage_shrink 的强时序假设，修"乱序流退化"问题；把 B 的隐藏段证据补足后再决定是否默认 adapt。
- **A**：探索无监督域适应（CORAL/TCA 类）解决乙醛类跨批不可迁移；把"标签稀缺"下的 pair 阈值校准做得更稳。
- **策略层**：用连续超参搜索 + LLM 规划替代固定配方清单；把 damage_shrink 等强配方显式加入 kernel 的候选清单与知识注入（当前已知差距）。
- **记忆层**：完成 `--memory on/off` 消融，给"18→13"一个因果结论；让技能库支持自动沉淀（SkillCurator 从成功实验自动生成技能）。
- **门控**：延迟标签/滚动窗口下的在线阈值校准；多任务联合调度与预算分配。
- **成本**：镜像裁剪；kernel 分层触发（只在漂移/停滞时调用 LLM，正常轮走确定性），把 LLM 成本压到"够用就好"。

**（3）研究层面 —— 我们想回答的问题**

- 受控 RSI 的"改进速率"与"安全性"如何权衡？门控越严越稳，但会不会错过真实提升？
- LLM 在受限动作空间内的探索效率如何度量？记忆/知识对探索的边际收益是多少？
- 经验库能否从"文本记忆"进化为"可组合技能"，让系统在新任务上零样本起步？

## 3.4 结束语

> 工业模型的自进化，难点从来不是"能不能改"，而是"**改得对、改得稳、改得清楚**"。智训引擎 RSI Harness 给出的答案是：让 LLM 负责提出假设，让确定性系统负责验证与否决，让每一次改进都留下可回查的证据。**这既是赛题要求的"受控 RSI"，也是工业落地真正需要的自我改进。**

# 附录 C：答辩 Q&A 预案（10 问）

**Q1：你们和 AutoML / 超参搜索有什么区别？**
AutoML 是"一次性搜索一个静态目标"；我们是"在数据流上持续做诊断—实验—门控—沉淀"，而且要处理漂移、标签延迟、不能退化的工业约束。更本质的区别：AutoML 没有"经验"，我们的系统跨轮/跨 run 复用记忆与知识（18→13 的工具调用就是证据）。

**Q2：LLM 到底做了什么？是不是装饰？**
LLM 在 kernel 路径完成自主决策：观察 state → 生成漂移假设 → 设计 1–3 个实验 → 评估候选 → 决定 promote/retain/rollback → 写记忆。真实 A 运行 0.7032→0.7207、B 678→602 是它自己跑出来的。同时我们主动说明：确定性 pipeline 路径同样能拿主结果，LLM 是"能力上限与过程可解释性"的来源，不是唯一依赖。

**Q3：怎么保证 LLM 不乱来？**
四道闸：① 无 shell/文件/网络，只有 19 个受限工具；② 候选必须命中白名单策略与参数区间，执行器二次校验；③ promote 必须由确定性门控重算，LLM 只能更保守；④ 全动作审计 + 预算 tripwire。实测 Guard 拒绝过非 train 数据、第 4 个实验、无依据 promote。

**Q4：A 的 report 集为什么降了？是不是过拟合 selection？**
不是。三层互斥切分下 selection 只用于门控、report 从不参与选型。A 的验证集只有单批次，静态场景没有漂移可适应，所以收益有限（report −0.43% 在噪声范围内）；A 的收益在批次流（官方 8 批 +6.7%、外部 hidden 约 2.8 倍）。我们按场景分层报告，不混口径。

**Q5：B 的基线比常数还差，你们的提升是不是"修坏基线"？**
是，而且这正是赛题的工业价值：先诊断出"官方基线本身失效"，再修复。但我们同时披露：B hidden 段证据混合，路由标"待验证"；不会把 409.7 说成"隐藏集也能 −39.6%"。

**Q6：提升会不会是种子运气？**
门控阈值 = 2×种子噪声（A 0.004 / B 5.0 / C 0.3）；关键结论跑 seed 42/43 双种子；两次独立 strict 运行逐位一致；基线可逐位复算。若提升小于阈值，我们一律 retain（C 就是例子）。

**Q7：外部数据合规吗？**
外部 UCI 数据只用于**验证/测试床**，不进训练、不进提交谱系；`RSI_ALLOW_EXTENDED_DATA=0` 是默认且正式口径；隐藏标签任何阶段不可见；批次协议保证"当前批标签预测后才揭示"。这一点在 docs/11 与 docs/25 有完整披露。

**Q8：6 小时 / 资源预算怎么满足？**
3×10 轮 30 分钟 / CPU 1059s / 56 实验 / 0 token；kernel 路径 3 轮约 24 分钟 / 44 万 tokens（平台预算 800 万）。预算硬上限与 92% tripwire 写在设计里，还有降级阶梯兜底。

**Q9：如果评测环境没有 LLM / 断网怎么办？**
自动降级确定性 planner（pipeline），仍能完成 10 轮并保证不低于基线；LLM 只是"更聪明的探索者"，不是运行前提。这条路径就是我们的 canonical strict 结果。

**Q10：这套东西怎么迁移到真实工厂？**
task.json 契约 + workspace v2 适配 + 可替换的知识库/记忆 + 镜像化交付。未知任务 D 已在零代码改动下跑通 4 批，证明"运行时与任务解耦"；换新模型只需接一个 task.json 和 checkpoint。
