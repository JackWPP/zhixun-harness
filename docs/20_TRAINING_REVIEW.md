## 当前实现缺口

1. **缺平台批次适配器。** `python -m rsi.cli run` 从公开 JSONL 构建本地 train/calibration/selection/report 切分；没有 `batch_id`、提交决策再取下一批、历史重放去重或评测端要求的 checkpoint 发布响应。当前 JSONL `predict` 只满足单条预测契约，不能代表比赛主协议。
2. **标签时序没有被协议化。** 会议说批次带标签、每批必须先输出决策，但没有精确说明当前批标签和历史标签分别何时可见。训练入口必须把“当前批预测”和“上一批已揭示标签的训练/评估”隔离；在读到 SDK 契约前，不允许按本地设想使用当前批标签。
3. **SwanLab 未完成。** `rsi/runner.py::_init_swanlab` 明确使用 `mode="offline"`，`_swan_log` 当前只记少量轮次指标。需要依据官方规范在线同步工业模型训练过程、设置公开权限、取得可访问 URL；比赛网络禁令与 SwanLab 出站路径如何兼容尚未确认。
4. **驱动端点未验证。** 已做的 Tokenplus A×1 验证只证明开发期工具调用基本可用；不能当 PyTRiO endpoint、鉴权、usage、超时和网络限制的通过证据。
5. **发布证据不完整。** 引用的 2026-11-15 canonical Kernel run 和 `harness.tar` 当前不在 checkout；A/B/C base checkpoint 本地仍在且 SHA 一致，但不能据此宣称镜像满足 2GB 限制或正式基线来源已经确认。
6. **实际 Kernel 效果还未证明稳定。** 2026-11-16 的 A×1 10-turn 运行调用 16 个工具、评估 3 个候选，最终 retain 在 baseline macro-F1 0.703220；这是一条有效的负结果，不是自主提升证据。

## 实施顺序与实验闸门

| 阶段 | 工作 | 通过条件 |
|---|---|---|
| 0 · 平台契约 | 从当前提交页/SDK 找到输入输出 schema、批次 ID、标签可见时点、下一批触发、状态持久化目录、模型上线/回滚响应和公开记录规范 | 形成带版本和原始样例的契约文档；每个字段有来源；平台试运行次数仍不消耗 |
| 1 · Harness 协议 | 增加 batch adapter：读入当前批、用已上线 checkpoint 先预测、输出 prediction + promote/retain 决策，再允许后续批；历史重复重放幂等；只有已解封标签可训练；完整状态写 `/work` | A/B/C 固定 JSONL replay 和逐批真实管道等价；断点恢复、重复批、错误输入、时间/内存限制测试通过 |
| 2 · 记录链 | SwanLab adapter 记录工业模型实验与门控，保留本地 JSONL/SQLite；验证可公开访问的 URL，检查公开内容不含密钥和隐藏标签 | 至少 3 次完整尝试；SwanLab run 链接公开可读；记录包含假设、数据版本、候选、指标、父子 SHA、决策和资源 |
| 3 · 远端基线 | 在 4 核/8GB Linux Docker 上对 A/B/C 跑 static baseline、批次回放及至少 2 个 seed；使用真实平台批次次序，不发 LLM 请求 | 输出契约通过；全批耗时/峰值内存记录；基线与官方参考一致；image tar <2GB，容器里无模型权重和 embedding |
| 4 · 受控 RSI | 先做策略层、模型层和联合策略三组消融；每次 ≤3 候选，严格 train/已揭示标签训练，selection 做门控，审计层保留 report/probe，Agent view 不可见；SwanLab 连续记录三次以上尝试 | 跨任务、跨 seed 评估平均增益、最差批次、回滚恢复、时延和资源；负收益候选安全 retain；不靠一次提升上线 |
| 5 · PyTRiO preflight | 用官方允许的 endpoint/model ID 运行 agent tool call、usage 记账、超时恢复、断网降级和 SwanLab 网络验证 | endpoint 是 PyTRiO 的准确可用模型，端点与密钥只通过安全环境注入；正式 preflight 全绿 |
| 6 · 冻结提交 | 固定 source commit、container digest、tar SHA、模型配置和公开记录链接；检查所有文件及依赖许可 | 复现包完整，平台输入输出契约通过，记录链接可访问，人工确认后才消耗正式试运行额度 |

## 优化假设

- **A · 气体传感器：** 重点测无标签输入漂移触发的轻量 recenter 与候选门控。现有结果对小样本类别敏感，按批/类别同时报告 macro-F1 与置信区间，并保留最差漂移批表现。
- **B · 轴承 RUL：** 重点比较 damage-shrink 和 train-only 受限续训。验证按设备/批次分组，不能把同一设备相邻行随机拆分后当独立证据。
- **C · 发动机 RUL：** 公开 validation 尚未显示明显漂移时应把 retain 作为强基线；测试漂移检测的误报率与资源开销，避免为了“每轮都更新”造成退化。
- **跨任务 Harness：** 预置只读漂移诊断与实验设计技能；记忆只写入通过 selection 门控、可复现且说明适用范围的结论。技能更新先走临时副本、review、版本化 promote/rollback。
