Why RSI

一次性训练，在漂移的工业数据上注定“慢慢失准”

赛题要的不是“再训一个更准的模型”，而是一个能在批次数据流里自主维持并提升工业模型的 harness。 起点只决定下限，能力体现在批次流开始之后。

🧊 传统做法：一次训练，长期使用

  • 01 用固定训练集训一个 checkpoint
  • 02 上线后不再变化（或人工定期重训）
  • 03 分布漂移 → 误报/漏报悄悄升高
  • 04 发现问题时往往已经失准很久

🤖 我们的做法：受控 RSI 闭环

  • 01 每批新数据到达，先交付当前预测
  • 02 检测漂移、诊断归因、生成候选策略
  • 03 小规模实验 + 公开验证门控
  • 04 通过才上线，失败可回滚；经验写进记忆
Architecture

六层结构：大模型负责“想”，护栏负责“不许乱来”

驱动模型用赛事指定的 Qwen3.8-27B；真正的训练/评估/上线由确定性组件执行。LLM 只能提候选，不能绕过门控。

01
平台入口 v2 /app/harness.py
describe / train / predict 三命令，适配 contest.harness.workspace.v2；每轮读 /data、/previous、/state。
02
Supervisor 调度
预算、墙钟、数据切分、记录与报告；保证整轮 train 可中断、可追溯。
03
Agent Kernel 决策
观察 → 诊断 → 提案 → 跑实验 → 比较 → 决策；具备记忆与知识库检索，跨轮复用经验。
04
Guard 安全边界
白名单、预算上限、只允许官方训练数据、路径/注入扫描；决策只能用 selection+margin 复算，LLM 只能更保守。
05
Experiment + Memory
worker 子进程训练，checkpoint 谱系与 sha 可追溯；SQLite+FTS5 存 lessons / strategy_stats / skill_usage。
06
Records + Dashboard
JSONL 审计真源、state v3、实时看板；workspace_report 满足平台字段约定。
入口：python3 /app/harness.py describe|train|predict 镜像：378 MB，离线，无外网依赖 每轮至少一次真实模型调用，且必须留下 call id
Batch Protocol

一批一批地来：先交预测，再揭标签，hidden 永不解禁

这是整份证据的关键。早期版本曾把“当前批验证标签”混进训练包，数字会虚高；现在重写为诚实协议。

STEP 1

数据到达

当前批只有输入、没有标签；历史批已揭示的部分进入训练集。

STEP 2

先交付预测

对当前批输出预测；这是“上线前的判断”，不能等答案。

STEP 3

标签揭示

预测交付后，当前批标签才可用于事后评分与下一轮决策。

STEP 4

写入历史

已揭示的行进入下一批可用历史；hidden 批只预测、永不解禁。

STEP 5

下一批 → 回到 1

每次都会重给之前全部历史数据；循环直到轮次用尽。

🔒
不变性验证 E0：把当前批 answers 打乱后，decision.json 与 predictions.jsonl 必须逐字节不变 —— 已通过。 这证明 RSI 的决策没有偷看当前批答案。

Honesty

主动讲清楚的边界

这些不是扣分项，而是评委最容易追问的点；先讲反而加分。

⚠️ 答辩/PPT 里要主动声明的六件事

  • 外部数据 ≠ 平台隐藏测试流。UCI Gas Drift 是我们能找到的最接近 A 漂移的公开数据，用来搭批次流测试床；平台私有包未知，不宣称同分。
  • B/C 是混合结果。B 在 arrival 段 adapt 显著更好，但 hidden 尾部 frozen 更好，我们标注“混合/待更多批验证”；C 无漂移时 adapt 有害，因此路由 frozen。
  • selection 子集有噪声。A 的 selection 只有 435 行，早期批指标波动大；用 margin 门控 + 后续批复核，但没有隐藏标签，无法完全消除。
  • 外部数据默认关闭。镜像 RSI_ALLOW_EXTENDED_DATA=0，外部数据只做测试床，不进正式提交训练谱系；所有数字都标了口径。
  • trial 以平台报告为准。本地提交路径数字来自独立 predict；平台 trial 当时仍在 running，最终分数看平台。
  • “递归”是受控、有界的。不宣称无限自我进化；证据是“给定漂移数据流，在有限轮次内持续检测—适应—验证—上线”，以及跨 run 的记忆/策略积累。
