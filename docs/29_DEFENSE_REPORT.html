01

背景：一个真实的问题，一个特殊的赛题

工业模型上线之后，数据会变，模型会「越用越差」；人工调参又慢又不可复现。赛题要的正是这件事的自动化答案。

1.1 问题：模型上线后，为什么「越用越差」？

设备老化、环境变化、工况切换……训练时见过的数据（分布），和上线后遇到的数据，已经不是同一份数据了。

数据分布漂移（distribution drift）示意可截图
同一个模型、同一套权重，训练时分数很高；上线几个月后，传感器老化、环境温湿度变化，输入分布整体偏移，模型没见过这样的数据，性能就掉了。这不是模型「坏了」，而是世界变了。
原因一

设备在老化

传感器灵敏度、基线、噪声水平随时间和批次缓慢变化——A 任务的气体传感器就是典型：不同批次测到的「同一种气体」读数不一样。

原因二

环境/工况在变

温度、湿度、负载、操作习惯变化，导致输入特征的统计分布改变。冷启动、换季、换产线都会触发。

原因三

人工调参不可持续

靠工程师半夜盯指标、手动调参、重新训练：慢、贵、不可复现，而且「救得了一时救不了一世」。

讲法一句话说明背景：工业现场没有「一次训练、终身使用」的模型。真正的问题是——数据一直在变，模型能不能自己发现、自己适应、而且改得让人放心？

1.2 赛题在考什么？三个关键词

赛题是「工业制造场景下的模型训练与超参数优化」，但它的要求远不止调参——本质是让系统在有限预算内持续、可信地自我改进。

要求 1

持续保持并提升性能

在有限的学习与标注预算内，系统自动让模型维持在基线上方，并能应对数据漂移；不能人工介入。

要求 2

受控、可回滚、安全

自我改进不能失控：改了什么、为什么改、改坏了怎么办，都要有边界、有兜底、有回滚路径。

要求 3

过程可核验

至少 3 次完整的「读历史 → 做实验 → 依据结果决策」记录；还要能复现、能被审计，不能自己编数字。

关键判断主观评分里「方法设计 + 实验分析」占了很大比重。所以我们的策略不是去抠 0.01 的分数，而是把方法讲清楚、把实验记录做扎实、把边界主动讲明白——可信比好看更重要。

1.3 三个任务：三种「坏情况」

三个任务刚好覆盖了工业模型的三种典型困境：会漂移的、基线本身就是坏的、根本不该乱改的。

任务 A · 气体分类

传感器漂移：该适应

数据：UCI 气体传感器阵列，128 维、6 类气体，按批次采集。
指标：macro-F1。
陷阱：训练只有 batch1，验证只有 batch2，中间隔了几个月——传感器在老化，「同一种气体」读数变了；有的类别跨批几乎不可迁移。

→ 这是最典型的「漂移」场景，也是 RSI 应该大显身手的地方。

任务 B · 轴承寿命预测

坏基线：先修好，再谈提升

数据：XJTU-SY 轴承全寿命，34 维特征，预测剩余寿命（分钟）。
指标：RMSE（越低越好）。
陷阱：官方基线 RMSE 681，比「直接猜常数均值」的 536 还差——基线本身是坏的；而且验证集 90% 的行来自同一个轴承。

→ 提升空间很大，但必须用「诊断驱动」的方式修，而不是瞎调。

任务 C · 发动机寿命预测

无漂移：考你「不乱改」

数据：NASA C-MAPSS，24 维传感器，预测剩余寿命（cycles）。
指标：RMSE。
陷阱：验证集是同分布随机切分，根本没有漂移对象。这里瞎改反而掉分，正确的动作是识别「不用改」并保持。

→ 自我改进系统最难的不是「改」，而是知道「什么时候不该改」。

1.4 为什么传统做法不够？

做法一

人工调参 / 定期重训

依赖工程师经验，响应慢、成本高、不可复现；换一个任务就要重来一遍，无法沉淀方法论。

做法二

一次性微调 / AutoML

只解决「这一次」的优化，不处理「下一次」的漂移；搜索空间大、试错成本高，而且搜完就结束了，不会记住经验。

做法三

让大模型「自由进化」

听起来很酷，但不可控、不可复现、不可审计；工业场景里一次乱改就可能造成事故，不能这么用。

所以我们要的不是「更强的调参器」，而是一个受控的、能自我迭代、并且改得让人放心的系统——这就是受控 RSI（递归自我改进）。第二部分讲我们怎么把它做出来。

每一轮就是一次完整的「科学方法」：观察 → 假设 → 实验 → 评估 → 决策 → 记忆，然后进入下一轮。

记忆不是点缀，是「递归」的关键：每一轮把「什么有效、什么无效、为什么」写回记忆 / 技能 / 知识库，下一轮先读历史再做决策——这就是「自我改进」能跨轮、跨运行复利的原因。
普通调参器做完一轮就结束了；我们的每一轮都在为下一轮积累经验，而且每轮结束都能「回到历史最优」，不会越改越差。

2.3 我们理解的 RSI：三层递归

RSI（Recursive Self-Improvement）不是「让模型改自己的代码」。我们的定义是：在固定目标和固定行动空间内，让系统自主完成「观察→假设→实验→评估→决策→记忆」，并让改进能力跨轮、跨运行复利。

2.4 四个「厉害的技术点」

这四个点分别解决四个问题：分数可不可信（01）、系统可不可控（02）、适应快不快/省不省（03）、改得稳不稳（04）。

TECH 01

三层互斥切分——先保证「分数可信」

先把「报告分数」和「选型分数」分开：报告用的数据，绝不参与选模型。
  • 官方 validation 切成三份互斥子集：calibration（校准）/ selection（门控）/ report（报告），互不重叠；
  • 门控只看 selection，report 只在最后报告；A 另加一条外部 UCI 探针，只验证、不训练、不选型；
  • 跑两次独立 strict 运行，指标逐位一致；打乱答案后决策文件逐字节相同（E0 不变性测试）。
两次运行逐位一致E0 不变性通过
TECH 02

受控 Agent——LLM 提议，系统把关

LLM 只当「提议者」，能不能执行由确定性系统说了算。
  • 19 个受限工具，没有 shell、文件、网络权限；只能用工具观察、提议、提交；
  • Guard 白名单 + 执行器二次校验 + 统计门控，三道关卡；LLM 只能「更保守」，不能「更激进」；
  • LLM 不可用或连续失败 → 自动降级为确定性 pipeline，run 不中断。

TECH 03

推理期校准——零训练，秒级适应

一个参数都不训练，也能让模型「跟上」新批次的数据。
  • recenter：按新数据的统计量，把模型输出映射回原来的坐标系（不碰权重）；
  • shrink / damage_shrink：当模型在某类数据上明显不可信时，把预测向安全中心收缩；
  • 全部改动秒级完成、可秒级回滚，checkpoint 字节不变——最便宜的适应方式。

TECH 04

统计门控——没把握就不改

门控阈值 = 2 倍种子噪声；宁可保持，也不乱动。
  • 阈值按任务标定（A 0.004 / B 5.0 / C 0.3）：提升超过阈值才采纳，掉点就回退，其余保持；
  • 最终交付的永远是历史最优，而不是「最后一轮碰巧好的」；
  • 三个任务的实际行为高度一致：采纳一次后，连续拒绝噪声（见下方时间线）。

2.5 支撑技术：让「聪明」可持续

记忆

三层记忆 + 技能

工作记忆（每轮快照）、长期记忆（跨 run 的任务笔记）、经验索引（SQLite 记录每轮实验与教训）；技能用 SKILL.md 按需展开。跨 run 首轮工具调用 18 → 13，越跑越少走弯路。

知识

12 篇离线知识库

评测环境禁外网，Agent 查不了论文。我们把漂移诊断、校准方法、实验设计等 12 篇知识离线策展、FTS5 索引，按需检索——知识只扩大「分析思路」，不扩大「操作权限」。

审计

全链路留痕 + 离线镜像

每轮记录：假设、变更、指标、父子 checkpoint sha256、token 用量、Guard 审计；JSONL 为真源可重建。镜像 376MB、CPU-only、离线可跑，不依赖任何在线服务。

2.6 工程化落地：从「本地 harness」到「可提交系统」

平台对接

workspace v2：describe / train / predict

按官方评测协议实现三个入口：describe 声明任务；train 处理每轮数据并返回候选模型；predict 逐行输出预测。平台每轮投喂数据，我们内部完成一轮完整 RSI。

通用性

未知任务 D：零代码跑通

换一个完全没见过的任务，只提供 task.json 和 checkpoint，系统不改一行代码跑通 4 个批次、0 errors——证明它是通用 RSI 运行时，不是给三个任务特调的脚本。

03

性能 benchmark：先证明「分数可信」，再谈「分数多高」

严格官方数据口径下，三个任务全部不低于基线；在真正有漂移的场景里，提升被放大到 2.8 倍。

3.1 评测口径：三个约定

约定 1

三层互斥切分

validation 切成 校准 / 门控 / 报告 三份互斥子集：选型只看门控集，报告只看报告集，谁都不许「既当运动员又当裁判」。

约定 2

2 × 种子噪声阈值

门控阈值 = 2 倍种子波动（A 0.004 / B 5.0 / C 0.3）。小于阈值的「提升」一律当作噪声，不采纳。

约定 3

固定种子 + 逐位复现

固定 seed=42（关键实验另跑 seed=43）；两次独立 strict 运行指标逐位一致，基线分数可逐位复算。

讲法很多队伍会直接报「验证集分数」，但这在方法上站不住：用来选模型的分数，不能再用来报成绩。我们先把这个坑填上，后面的数字才可信。

04

总结与展望

我们做的不只是一个「调参器」，而是一套让工业模型可持续自我改进、并且改得让人放心的系统。

4.1 四句话总结

01 · 问题
工业模型「越用越差」是结构性问题，不是调参能解决的。

数据一直在漂移，静态模型必然衰减；人工调参又慢又不可复现。

02 · 方案
我们用「受控 RSI」把改进过程工程化：诊断 → 假设 → 小步实验 → 门控采纳。

LLM 只提议，确定性系统验证与否决；每次改动可回滚、可审计。

03 · 结果
三个任务全部不低于基线：A +4.5%、B −39.6%、C −9.4%（门控集）。

在真正有漂移的场景，A 提升约 2.8 倍；30 分钟、0 token 完成 3×10 轮无人干预。

04 · 价值
可复现、可审计、可迁移：两次运行逐位一致，未知任务零代码跑通。

它是通用 RSI 运行时，不是给三个任务特调的脚本。

4.2 方法论沉淀（可以带到下一个项目）

原则一

先可信，再智能

评测口径先立住（三层切分、噪声阈值、逐位复现），否则再花哨的方法都不可信。

原则二

先兜底，再自主

先保证「LLM 挂了也能跑完、且不低于基线」，再追求「让 LLM 更聪明地探索」。

原则三

敢于否定自己

发现旧协议有标签泄漏，主动作废整批数字、重建诚实协议——自我改进系统首先要能自我批判。

4.3 三层展望

近期 · 3 个月

打满评测链路

等待平台开放试运行，完成官方 trial；补强 kernel 候选清单（把 damage_shrink 等强配方显式加入），让 LLM 路径追上确定性路径。

中期 · 6–12 个月

更多任务类型

从分类 / 回归扩展到检测、时序预测、多模态；行业知识库按场景替换；支持多任务联合自进化。

长期

产品化：模型健康度运维

把「漂移诊断 + 受控 RSI」做成工厂侧的模型健康度基础设施——模型上线后持续自我维护，人只做审批与审计。

结束语我们相信：未来的工业模型不是「一次训练、终身使用」，而是像设备一样被持续运维。RSI 就是这套运维能力的引擎——而「受控」，是它能在工业现场活下来的前提。

附录 C：答辩 Q&A 预案（6 问）

点击展开参考答案；每题控制在 30 秒内讲完。

Q1：提升会不会只是种子运气？

不是。门控阈值本身就是 2 倍种子噪声（A 0.004 / B 5.0 / C 0.3），小于阈值的提升一律不采纳；关键实验跑了双种子；两次独立 strict 运行指标逐位一致；官方基线分数可以逐位复算。如果提升没到阈值，系统会保持原模型（C 就是例子）。

Q2：用了外部数据，合规吗？

外部 UCI 数据只用于「验证 / 测试床」：不参与训练、不进提交谱系、不计提交分；默认且正式口径是 RSI_ALLOW_EXTENDED_DATA=0；批次协议保证当前批标签在预测完成后才揭示，隐藏标签任何阶段不可见。

Q3：如果评测环境没有大模型 / 断网怎么办？

自动降级为确定性 pipeline，run 不中断。事实上我们主结果（56 实验 / 0 token）就是完全不用 LLM 跑出来的；LLM 只是「更聪明的探索者」，不是运行前提。

Q4：和 AutoML、大模型微调有什么区别？

AutoML / 微调优化的是「这一次」的模型；我们优化的是「改进过程」本身：诊断驱动、小步可回滚、门控决定采不采纳，并且把经验沉淀下来跨轮复利。我们也不改模型结构，只做受控的小步改动和推理期校准。

Q5：30 分钟 / 0 token 是怎么做到的？

因为最大的收益来自「推理期校准」而不是重训：B 的 −39.6% 主要是后处理校准（零训练、秒级）；56 个实验都是小步验证；再加上时间/实验数/token 的硬预算和门控，避免了无效的反复折腾。

Q6：这套东西怎么迁移到真实工厂？

三个支点：① task.json 契约 + workspace v2 适配，换任务只换配置和 checkpoint；② 知识库 / 记忆可按行业替换；③ 镜像化离线交付（376MB、CPU-only）。未知任务 D 已经零代码改动跑通 4 批，证明运行时和任务解耦。

数据口径声明：主结果均为严格官方数据口径（RSI_ALLOW_EXTENDED_DATA=0，只用官方 train；validation 仅用于校准/门控/报告），两次独立运行指标逐位一致；外部测试床（UCI 批次流 / Track X）只验证不训练、不计提交分；全量彩排属开发期证据，未提交、未复验。详细证据与逐条索引见 docs/28_PPT_REPORT.md 与 docs/12_EXPERIMENTS.md。
