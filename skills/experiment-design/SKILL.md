# 何时用
诊断完成后、调用 propose_experiment 之前。

# 步骤
1. 先写父模型 SHA、数据可见性和固定评估窗口；每个实验只改变一个因素：策略、学习率、epoch、后处理类型或混合权重。
2. 假设写成"如果 X，则 selection 主指标相对父模型改善至少 margin，且最差批/关键组不恶化超过界限"，说明作用机制与可能证伪它的观察。
3. 同轮保留一个 parent/retain 对照；候选最多 3 个，先跑低成本校准，再考虑训练。参数必须在策略目录范围内。
4. 晋升前核对 selection 增益是否超过固定噪声门槛、最差批/组是否越界、checkpoint 是否可恢复、资源预算是否足够。若只看见一次小幅上涨、证据区间跨过零或诊断不确定，选择 retain。
5. 分类任务同时检查每类支持数。低支持类别不能单独驱动晋升；主 macro-F1 达标但支持充分类别宏平均下降时，保留父模型并换一个机制继续实验。不要反复微调同一个参数追逐极小类别。
6. report/probe 只供独立审计，不能帮助选策略、改阈值或写入后续 agent memory。若 report 显示选择指标改善但审计表现退化，把差异作为风险记录，不从 report 反向调参。
7. 预期风险写清楚（过拟合、漂移加剧、预算消耗）；实验完成后记录实际指标、决策和可复现工件哈希，不把预期效果写成结果。

# 坑
- 不要在同一轮同时改学习率和后处理权重，否则无法归因。
- 不要用 report split 或 probe 指标做选择；同时不要把单一 selection 主分数当成稳定性证明。
- 训练/拟合数据只能用 train；selection 只用于公开候选选择。

# 验收
每个实验都有：父 SHA、策略、参数、后处理、假设、预期效果、风险、最差组保护和资源预算；执行后用 selection 证伪，report/probe 留给审计。
