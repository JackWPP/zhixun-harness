# 何时用
平台或回放以批次流提供输入、重复批次、延迟标签或进程恢复时。

# 步骤
1. 只根据已确认的官方 SDK/schema 解析回调和字段。方法名相似不代表签名相同；契约未知时暂停适配，不猜 `start/candidate/save_state/complete` 参数。
2. 开始批次时校验稳定 batch ID、序号、输入摘要和当前 champion SHA。相同 ID、相同负载是重放；相同 ID 的内容、序号或模型版本冲突时拒绝。
3. 预测阶段只读取本批可见输入和前序已揭示状态。先固定并持久化预测、预测模型 SHA 和候选评估结果，再提交 promote、retain 或 rollback 决定。
4. 决定提交前，当前批标签不可读取、训练、统计、提示、记忆或用于调参。隐藏标签、report、probe 永远不进入 agent 工具视图。
5. 只有平台明确解封后才评分当前预测，并将新可用标签放入后续训练状态。每批结束后保存标签摘要、选定 champion SHA 和状态版本，再请求或处理下一批。
6. 恢复时重载已提交状态并幂等重放；不要重复训练、重复提升版本或覆写已提交预测。回滚只能切回已保存且哈希验证过的父模型。
7. 每次循环留下可审计事件：输入摘要、预测模型、策略/skill 版本、假设、候选、selection 证据、门控结果、标签解封时点、最终 SHA、CPU/wall/token 用量和失败原因。

# 坑
- 本地批次模拟不等同于官方 workspace 协议；adapter 必须由官方契约字段驱动。
- 无标签协变量监测只能报告输入变化，不能声称检测到性能退化或概念漂移。
- 标签解封后评估的是先前已固定模型的预测；不得用后来更新的模型重算来代替线上实际结果。
- promote、retain、rollback 都是完整决策；没有通过门控的候选应 retain 或 rollback。

# 验收
每个批次都能回答：读到了哪些数据、何时决定、哪些标签何时解封、是否发生重放、恢复后模型 SHA 是什么，以及该批是否改变了下一批可见状态。
